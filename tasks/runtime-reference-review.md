# Runtime reference review

## Verdict

The guide is explicitly an unstable, version-specific reference. Against the installed server at `cf5030f15781637498be86debe26fcf102f5690d`, I found two differences worth version-scoping and one client-compatibility point that remains unknown. I did not compare the guide with the current upstream `unstable` branch. I found no demonstrated plugin defect in these differences and no duplicate-prevention defect in the current transaction path; a SQL unique constraint is not the only way to satisfy that invariant.

## Version-specific differences

1. **The plugin validates a narrower ACK shape than the core consumes.** The guide says `_speech` reads `speaker`, `listener`, `speech`, and `location` as required fields (`plugin-runtime.md:62-80`). Core inserts `$speech["location"]` directly into the speech row (`/var/www/html/HerikaServer/processor/comm.php:680-690`). The plugin requires only `speaker`, `listener`, and `speech` (`server/prerequest.php:527-539`) and does not use `location` in its evaluation or persistence. Thus a valid-ID ACK without `location` passes plugin preflight. That is a shape difference, but this review did not establish a correctness failure in supported traffic. **No validation change is justified solely to mirror an unused field**; revisit if a supported client/core path demonstrates that accepting its absence changes behavior or causes a failure.

2. **The `execQuery()` return description differs from this installed revision.** The guide says it returns an empty string on success and an error string on failure (`plugin-runtime.md:118`). Installed `sql::execQuery()` calls `pg_query()` and returns that raw result; on failure it logs and returns `false` (`/var/www/html/HerikaServer/lib/postgresql.class.php:325-347`). It also calls `re_connect()` before the query (`:328`). This confirms a difference for the inspected SHA only; it does not establish that the description is wrong for the guide’s current unstable source. The plugin avoids this wrapper inside its atomic write transaction and uses its retained native connection (`server/store.php:1004-1016`), appropriate for the inspected helper behavior.

## Reviewed choices that are sound for this implementation

- **Missing speech IDs fail closed.** The plugin validates required text fields first, then returns `untracked-speech` with reason `utterance_id_absent` for absent/blank IDs; malformed nonblank IDs remain invalid (`server/prerequest.php:561-568`). The final log outcome is `skipped`, so existing dashboard outcome filters need no new value (`server/prerequest.php:273-291`). Core itself trims the ID and has a text-based fallback matcher (`processor/comm.php:641`, `:700-706`, `:835-880`); the plugin correctly does not use that weaker fallback for writes.
- **The plugin’s ID format is narrower than core’s.** It accepts only `utt_[A-Za-z0-9_-]{8,128}` (`server/prerequest.php:565-568`), while this core handler merely trims and queries the supplied string (`processor/comm.php:641`, `:700-706`). The guide’s `example-001` is explicitly synthetic/observer-only, so this is not by itself a defect. Whether every supported client version emits the plugin’s `utt_` format is **unknown** from the inspected server source. Keep compatibility claims limited to a client version whose producer has been checked.
- **Player input uses an exact post-insert event snapshot.** Core inserts the request’s `eventlogInsert` at `main.php:1943-1959` and calls recursive `postrequest.php` hooks after core post-request handling (`main.php:2938-2943`). The plugin’s `server/postrequest.php:6-25` uses the captured event tuple and route-selected listener; it does not bind to the newest row or treat the input as an audio ACK. This matches the guide’s separate-timing warning.
- **The recursive-loader scope warning is accurate.** `requireFilesRecursively()` explicitly imports `$gameRequest` in `lib/data_functions.php:7928`; it does not pass the caller’s locals. The plugin uses the documented request/global state rather than assuming locals are inherited.
- **No active profile is handled by a documented plugin-owned scope.** The plugin resolves zero active profiles to `unprofiled`, one profile to its numeric ID, and ambiguous profile state to no context (`server/store.php:25-34`, `:807-845`). The plugin docs describe this as shared-server scope and warn that it does not identify separate Skyrim saves (`docs/mind-poisoning.md:15`, `docs/development.md:65`). That fits the guide’s explicit-scope alternative; it does not claim save isolation.
- **Duplicate prevention is serialized, not just a prior `SELECT`.** For persistence, the plugin takes a nonblocking advisory lock for the listener, begins a transaction on the retained connection, locks the listener row `FOR UPDATE`, then re-reads and checks the per-listener ledger under that lock (`server/store.php:957-980`, `:630-644`). It writes the relationship edge, plugin ledger and timeline in one update, inserts and verifies the matching NPC history snapshot, then commits; exceptions/failure return through rollback/release cleanup (`:983-1011`, `:1013-1063`, `:1065-1117`; orchestration `:656-685`, `:688-705`). Concurrent calls through this path serialize on the same listener and the second sees the committed event/utterance entry before writing. A unique constraint is therefore not required to establish this implementation’s per-listener duplicate invariant. A constraint would be warranted if operation identity moved to an independently written table or writers bypassed this serialization/ledger protocol; no such migration is justified by the guide alone.
- **The playthrough switch guard covers the synchronous request.** The core SQL constructor calls `ptr_runtime_enter()` (`lib/postgresql.class.php:15`); that acquires the shared `work.lock` lease for the whole request (`lib/playthrough_runtime.php:68-84`). The plugin also checks active scope before the model call and again in its persistence transaction. This is consistent with the guide’s stale-work warning for this synchronous path. It does not establish safety for a future detached worker.
- **The plugin does not misuse the relationship worker as a generic queue.** It performs the model call synchronously before persistence (`server/prerequest.php:691-711`) and documents the 12-second I/O timeout as not a hard wall-clock deadline (`docs/development.md:66`). The guide’s warning that `_rel*` queue/worker pieces are feature internals is compatible with this design; request latency remains an accepted tradeoff.

## Remaining uncertainty

The inspected server does not establish what every client release sends for `utterance_id`, nor whether missing `location` reaches the core insert in a supported client flow. Confirm those against the exact client producer before widening compatibility claims. This review does not certify provider, database runtime, audio delivery, or in-game behavior.
