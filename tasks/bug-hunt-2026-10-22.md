# Bug hunt 2026-10-22

Scope: `server/`, `plugins/private_conversation/server/`, and the test suites. I read the code and ran the tests on Linux with PHP 8.3. I did not use PostgreSQL, a model provider or an installed CHIM server.

Evidence levels:
- **REPRODUCED**: a script shows the wrong behaviour.
- **CODE**: the code path is clear but I did not run it (for example, it needs PostgreSQL).

## Fixed in this branch (tests only)

- [x] `tests/dashboard_integration_test.php` failed since 0.1.25. The fixture did not copy `restore_policy.php`, and one check expected old one-line markup. The product output is correct.
- [x] `tests/reflection_observer_test.php` failed since 0.1.20. It required a `persistence_finished` record in every case, but `provider_failure` never gets to persistence. This case runs only on POSIX hosts, so it did not fail on Windows.

## Open findings (not fixed)

### Medium

1. **A claimed-sender name that differs only in case creates a duplicate relationship.** `server/written_evidence.php:471` uses the envelope name, not the catalog `npc_name`. The identity checks use case-insensitive `sameActorName` (`store.php:1035`), but the edge is stored under the exact key.
   - Trigger: the catalog has `Jarl Balgruuf` and the envelope sends `jarl balgruuf`.
   - Result: the model sees prior aff 0/neutral instead of 60. The write adds a new key, `"jarl balgruuf"`. The relationship-type protection (romantic to suspicious) is bypassed.
   - Recipient names are compared exactly (`:246`), so the code is not consistent with itself. REPRODUCED.
   - Fix: use the catalog name, or require an exact match.
2. **In preserve mode with overhearing on, a bystander problem stops the addressed listener's update.** `server/prerequest.php:312-346` and `:435-446` return `restore-policy-audience-cap` / `-invalid` / `-unavailable` as the status for the whole request.
   - `docs/integration-api.md:111` and `server/README.md:71` say to skip the extras and continue with the addressed listener.
   - Trigger: 5 or more eligible extras, or a roster that the parser rejects. The addressed listener's update is lost and is logged as `failed`. REPRODUCED.
   - No test and no doc mentions these codes. The owner must decide which is correct: the code or the docs.
3. **A failed optional `nsfw_npc_data` read in a transaction breaks the whole reflection write.** `store.php:2847-2889` catches the error and returns null. PostgreSQL has already aborted the transaction (there is no SAVEPOINT), so `writeNpc` then fails with `write-listener-failed`.
   - Causes: a `FOR SHARE` lock timeout, a statement timeout, or a non-`jsonb` column.
   - Result: all affinity and type judgments for that reflection are lost, not only the arrangement change. The failure is safe (rollback). CODE.

### Low

4. **One long multibyte line blocks an actor's reflections.** The SQL filter at `store.php:2682` uses `char_length(e.data) <= 4096` (characters). The PHP check at `:2699` uses `strlen > 4096` (bytes) and throws for the whole history. A Cyrillic line of 2,100 to 4,096 characters is enough. Reflections then stay `reflection-history-unavailable` until 16 newer lines push the row out. `people` has no SQL length filter. CODE.
5. **One cleanup failure marks later clean operations on the same store as failed.** `PostgresStoreDb::cleanupFailed` is set at `store.php:2364` and `:3080` and never reset. It is read at `restore_policy.php:187` and `store.php:2225` for each operation. In overhearing batches one store serves up to 5 listeners. Only the logs and statuses are wrong. CODE.
6. **Two `request_finished` records for one evaluation.** This happens in preserve mode with overhearing on, no extras, and a locked addressed listener: `prerequest.php:455-484` together with `:150-155`. Dashboard counts can double. REPRODUCED.
7. **The connector ID check is looser than the model adapter.** `prerequest.php:956-959` uses `FILTER_VALIDATE_INT`, so `" 7"`, `"+7"` and `7.0` pass. `model.php:207-218` rejects them. The result is an error-level `failed` on every request instead of a `connector-invalid` skip. The behaviour still fails closed. REPRODUCED.
8. **Intimacy parser rejects a model reply wrapped in a ```json code fence.** `intimacy_request.php:82` does not remove the fence. `influence.php:1105` does. The model call is paid for and the result is dropped. REPRODUCED.
9. **The written-evidence envelope cap is stricter than the documented body limit.** `written_evidence.php:32` sets a 16,384-byte limit on the envelope. A 2,000 code point body of emoji encoded with standard `\uXXXX` escapes is over that limit, so the letter is rejected. REPRODUCED.
10. **The dashboard trusts loopback without a `Host` check (DNS rebinding).** `dashboard.php:25-34`. A hostile page that rebinds to 127.0.0.1 can read the dashboard and the JSONL download. Other CHIM pages probably have the same exposure. REPRODUCED on the server side only.
11. **The dashboard `q` filter matches JSON keys.** `dashboard_data.php:1794-1804`. `q=outcome` matches every record, and values that contain `"` or `\` cannot be found. REPRODUCED.
12. **The 2 MiB log tail drops one complete record when the cut falls on a line start.** `dashboard_data.php:194-196` does not check whether the byte before the offset is `\n`. REPRODUCED.
13. **PCV: a multi-line scene card gives a wrong "NPCs not nearby" error.** `index.php:41-43` accepts the `\r\n` from a textarea. `state.php:450` rejects control characters. `index.php:1173` reports this as an eligibility failure and logs `actor_unavailable`. REPRODUCED.
14. **PCV: opener detection reads the player-name prefix.** `preprocessing.php:310` passes `"<Player>: <direction>"`. If the player's name contains a member's name, that member always speaks first. REPRODUCED.
15. **PCV: the Logs page access check is broad.** `index.php:579-581` accepts any non-empty `REMOTE_USER`, which stock nginx `fastcgi_params` fills from a client Basic header. `index.php:540-560` trusts any private default gateway, not only WSL. The real exposure depends on the web server. The logs are sanitized. CODE.
16. **PCV: a pending free scene always says "nearest six".** `index.php:347-348` ignores `free_cap`. REPRODUCED.
