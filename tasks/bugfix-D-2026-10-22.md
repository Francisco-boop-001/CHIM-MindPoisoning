# Bugfix D — overhearing fallback and connector validation

## Changes

- Preserve-mode invalid, unavailable, and over-cap extra audiences now emit a fixed `overhearing_audience_skipped` reason and return to the ordinary addressed path. That path still performs its own lock, baseline/scope, and replay checks.
- Overhearing preflight first collects unique extra recipients that pass read-only identity, ledger, and subject checks. The four-recipient cap is evaluated before any extra recipient restore baseline is written; if more than four pass, the whole optional extra audience is skipped without extra-recipient state writes. In preserve mode this is deliberately conservative: a recipient that would later be fenced by a restore-scope baseline still counts toward the preflight cap. This keeps the cap bounded and avoids partial baseline writes before discovering an over-cap audience.
- With no eligible extras, the overhearing path now returns to the single ordinary addressed flow. This removes the duplicate `request_finished` on a locked addressed recipient while preserving the ordinary lock decision.
- Connector IDs use the existing `positiveConnectorId()` helper. Whitespace, plus-prefixed, and floating-point representations fail before the model is called.
