## Package/update behavior

- **Catalog/Plugin Manager path — confirmed.** In the installed `ui/server_plugin_installer.php`, the remote manifest version is substituted into the channel package URL (`:413-419`) and compared with the installed plugin manifest using `version_compare()` (`:421-426`). Installation extracts into staging and writes channel metadata (`:325-361`), removes the existing `ext/<name>` directory, then renames staging into place (`:363-369`). This path does not call the schema-4 package manager or preserve its installed-package record. This matches the guide's catalog-replacement description at `plugin-runtime.md:173`.
- **Schema-4 game-carried `.dwpkg` path — confirmed.** `ui/api/plugin_packages.php:27-53` exposes `probe`, `start-upload`, and chunk upload. `lib/plugin_package_manager.php:34-47` compares the requested version to its own installed-package record using exact `hash_equals()` string equality; any mismatch, including a lower version, requests upload. The record is stored separately under the package manager's state root (`:540-565`). The uploaded manifest version must also exactly match the version in the game-side filename (`:95-100`).
- **Split-route implication — confirmed from those separate code paths.** A catalog replacement can change `ext/<name>` without changing the package manager's record. A later file-sync probe can therefore skip when its requested version still equals that stale record, even if catalog files now differ; if the record is missing or has a different version, the file-sync path requests the upload. This is why the repository's one-source-per-server guidance in `README.md:11`, `server/README.md:5`, and `docs/mind-poisoning.md:43` is warranted. The guide states this ledger distinction at `plugin-runtime.md:192`.
- **`mutable_paths` — confirmed, schema-4 only.** The package manager validates outer-manifest `server.mutable_paths` (`lib/plugin_package_manager.php:326-350`) and copies only declared old files/directories into staged content before replacement (`:448-498`). The builder emits `schema_version: 4` and `server.mutable_paths: []` (`scripts/package.py:21,85-91`), so this plugin currently preserves no old payload path. The catalog installer has no corresponding preservation step; it removes and replaces the plugin directory. The schema-2 installed `manifest.json` and schema-4 `.dwpkg` envelope are distinct contracts, as `docs/chim-plugin-development.md:25` says.

## Assessment

No server package-manager defect was found in the reviewed version-equality, catalog-replacement, or mutable-path behavior. The repository's distinction between Plugin Manager repository archives and schema-4 file-sync packages is accurate. Keep the single-source warning.
