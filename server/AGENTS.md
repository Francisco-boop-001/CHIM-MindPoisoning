# Contributor notes

- Keep the plugin within the package allowlist and compatible with HerikaServer reference `cf5030f15781637498be86debe26fcf102f5690d`. Do not add core edits, credentials, arbitrary configuration, migrations, dependencies, daemons, or install scripts. The only approved operator control is the non-packaged `data/mind_poisoning.json` pause state described below.
- Keep the two source paths distinct. NPC speech uses `_speech` ACKs bound to exactly one event by utterance ID; use the ACK-reported speech for subject extraction and model evidence, require matching speaker/listener and an explicit non-broadcast target, and treat the text as the client's report rather than verified audio. Player-origin speech uses the separate `postrequest.php` path for `inputtext`, `inputtext_s`, `ginputtext`, and `ginputtext_s`; correlate the inserted row by its exact source tuple and use `input_<positive rowid>` in the existing correlation slot. Never synthesize an ACK or use fuzzy/tail matching.
- For the ACK path, require one NPC speaker and listener and skip Player listeners. For the Player-input path, require one resolved NPC listener and a unique supported input event; skip narrator, everyone/broadcast mode, or an ambiguous route or identity. `source_people` may include bystanders; the route-selected listener is the addressee. Set only the strict `speaker_kind=player` marker, without dedicated Player speaker-ID/name fields; optional debug `model_reason` may quote a name or brief game-text excerpt. Missing markers in legacy records do not mean Player. Both paths skip uncertain identities, more than 8 subjects, or speech over 12,000 bytes. Allow processing only while global interaction is enabled and the captured request generation remains current. Keep Off and stale-generation checks, including a post-model recheck, and preserve playthrough token/lease checks.
- Skip if global relationship processing is disabled or `NEVER_CLEAR_RELATIONSHIP_DATA=true`. Skip listeners with nonzero `lock_profile` or a manual relationship lock; `relationships_locked` uses PHP `!empty` semantics.
- Use only the configured `openrouterjson` or `openrouterjsoncached` connector. Do not select another connector or add retries. Preserve connector globals, use the existing I/O timeout of 12 seconds and 1024-token limit, and do not claim a hard wall-clock cap.
- Apply only model-validated integer deltas from -5 through +5, including zero; clamp affinity to -100 through +100. Preserve relation types and unrelated plugin/core fields. Never write native Skyrim relationship ranks or turn hearsay into shared world knowledge.
- Keep the synchronous model call outside transaction locks. For persistence, use the guarded `sql::$link` compatibility shim, retain one native connection, take the listener advisory lock and row lock, then commit the affinity, exact-event ledger, and full NPC/history snapshot together. Zero decisions still need a ledger entry and snapshot. Fail closed on transaction, write, or snapshot failure.
- In v0.1.10, cap transaction-local `lock_timeout` at 1,000 ms and `statement_timeout` at 3,000 ms, preserving smaller positive inherited values. They bound per-lock/per-statement waits, not total transaction/request time; do not infer timeout classes from PostgreSQL error text.
- If an event has the Player as subject or speaker, reject ambiguous legacy Player relationship aliases before the model call and revalidate them during commit; NPC-only events remain eligible.
- In v0.1.10, retain the optional operator control at CHIM root `data/mind_poisoning.json` before model work and again after model validation before persistence. Missing `data/` or control file preserves enabled behavior. Accept a readable `data/` directory symlink, but require the control itself to be a regular non-symlink file of at most 1,024 bytes containing either `{"enabled":true}` or `{"enabled":false}`; normal JSON whitespace is allowed, but duplicate keys and escaped key spellings are rejected. Invalid root/data/control fails closed with fixed `pause_control_invalid`, while `enabled:false` returns `plugin-paused`/`plugin_paused`. Do not log its path or contents. Keep the file outside the package, add no dashboard write endpoint, and never clear saved relationships or ledger state when pausing. A pause after the second read can race with persistence already starting.
- Bound dedupe to 128 IDs and maintain the numeric eviction floor. Skip events at or below the floor, including unseen out-of-order IDs. Core restore with `NEVER_CLEAR_RELATIONSHIP_DATA=true` rewinds plugin ledger state, so the hook must stay disabled under that policy.
- Include at most the last 8 relevant prior events from the same playthrough, with up to 8 subject judgments per event, as untrusted prompt context; this is model guidance, not a cooldown or guaranteed repetition detector.
- Keep ACK payload rejection reasons as fixed codes, separate from payload contents; preserve skipped `invalid-payload`/`oversized` statuses and warning severity for malformed payloads, and never log raw request bodies or field values. Released v0.1.9 warned on absent `utterance_id` as `payload_utterance_id_missing`. In v0.1.10, only otherwise-valid absent or empty/whitespace-only string IDs are skipped as info `untracked-speech` / `utterance_id_absent`; present wrong-type or malformed IDs remain warning-level rejections.
- Removing the plugin stops future evaluations; it does not undo stored affinity or snapshots. Some upstream writers ignore the shared advisory lock and may overwrite a later plugin update. Fixture checks are not live PostgreSQL, provider, or in-game proof.
- Version 0.1.10 is a PRE-ALPHA development-candidate prerelease. It retains the server-side pause control, fixed ACK payload rejection codes, and transaction-local database wait bounds described above. Zero active CHIM Playthrough Saves profiles use explicit `unprofiled` shared-server scope; one active profile retains numeric isolation, while multiple, invalid, or ambiguous profile states skip. Auto-switch Off provides no unique Skyrim save ID, so another game save is not automatically isolated unless its database/profile changes. The Player path accepts four exact-correlated CHIM input types and one route-selected listener; it is not an audio ACK. A post-release shape-decoding analysis in the user-supplied `critique.md` report correlates all 18 observed `invalid-payload` warnings, including the six earlier noted, with valid ACK JSON lacking `utterance_id`; this instruction attributes that finding to the report, not an independent re-decode. Released v0.1.9 warned on absent IDs; v0.1.10 includes the skip for otherwise-valid absent or empty/whitespace-only string IDs, while wrong-type and malformed IDs remain warnings. The dashboard's `local=1` handoff changes navigation only; the existing loopback/authentication gate and gateway denial remain unchanged. The plain MO2 ZIP contains CHIM server data and may trigger MO2's Skyrim content warning; the FOMOD crash reported for v0.1.7 remains unresolved. Local fixtures do not prove live DB writes/concurrency, provider behavior, ACK/input delivery, installed dashboard authentication, native log delivery, or in-game acceptance. Test only in an isolated environment.
