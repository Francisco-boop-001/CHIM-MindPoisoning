# Contributor notes

- Keep the plugin within the package allowlist and compatible with HerikaServer reference `cf5030f15781637498be86debe26fcf102f5690d`. Do not add core edits, credentials, config, migrations, dependencies, daemons, or install scripts.
- Keep the two source paths distinct. NPC speech uses `_speech` ACKs bound to exactly one event by utterance ID; use the ACK-reported speech for subject extraction and model evidence, require matching speaker/listener and an explicit non-broadcast target, and treat the text as the client's report rather than verified audio. Player-origin speech uses the separate `postrequest.php` path for `inputtext`, `inputtext_s`, `ginputtext`, and `ginputtext_s`; correlate the inserted row by its exact source tuple and use `input_<positive rowid>` in the existing correlation slot. Never synthesize an ACK or use fuzzy/tail matching.
- For the ACK path, require one NPC speaker and listener and skip Player listeners. For the Player-input path, require one resolved NPC listener and a unique supported input event; skip narrator, everyone/broadcast mode, or an ambiguous route or identity. `source_people` may include bystanders; the route-selected listener is the addressee. Set only the strict `speaker_kind=player` marker, without dedicated Player speaker-ID/name fields; optional debug `model_reason` may quote a name or brief game-text excerpt. Missing markers in legacy records do not mean Player. Both paths skip uncertain identities, more than 8 subjects, or speech over 12,000 bytes. Allow processing only while global interaction is enabled and the captured request generation remains current. Keep Off and stale-generation checks, including a post-model recheck, and preserve playthrough token/lease checks.
- Skip if global relationship processing is disabled or `NEVER_CLEAR_RELATIONSHIP_DATA=true`. Skip listeners with nonzero `lock_profile` or a manual relationship lock; `relationships_locked` uses PHP `!empty` semantics.
- Use only the configured `openrouterjson` or `openrouterjsoncached` connector. Do not select another connector or add retries. Preserve connector globals, use the existing I/O timeout of 12 seconds and 1024-token limit, and do not claim a hard wall-clock cap.
- Apply only model-validated integer deltas from -5 through +5, including zero; clamp affinity to -100 through +100. Preserve relation types and unrelated plugin/core fields. Never write native Skyrim relationship ranks or turn hearsay into shared world knowledge.
- Keep the synchronous model call outside transaction locks. For persistence, use the guarded `sql::$link` compatibility shim, retain one native connection, take the listener advisory lock and row lock, then commit the affinity, exact-event ledger, and full NPC/history snapshot together. Zero decisions still need a ledger entry and snapshot. Fail closed on transaction, write, or snapshot failure.
- If an event has the Player as subject or speaker, reject ambiguous legacy Player relationship aliases before the model call and revalidate them during commit; NPC-only events remain eligible.
- Bound dedupe to 128 IDs and maintain the numeric eviction floor. Skip events at or below the floor, including unseen out-of-order IDs. Core restore with `NEVER_CLEAR_RELATIONSHIP_DATA=true` rewinds plugin ledger state, so the hook must stay disabled under that policy.
- Include at most the last 8 relevant prior events from the same playthrough, with up to 8 subject judgments per event, as untrusted prompt context; this is model guidance, not a cooldown or guaranteed repetition detector.
- Removing the plugin stops future evaluations; it does not undo stored affinity or snapshots. Some upstream writers ignore the shared advisory lock and may overwrite a later plugin update. Fixture checks are not live PostgreSQL, provider, or in-game proof.
- Version 0.1.8 is a PRE-ALPHA development-candidate prerelease. Zero active CHIM Playthrough Saves profiles use explicit `unprofiled` shared-server scope; one active profile retains numeric isolation, while multiple, invalid, or ambiguous profile states skip. Auto-switch Off provides no unique Skyrim save ID, so another game save is not automatically isolated unless its database/profile changes. The v0.1.7 Player path still uses four exact-correlated CHIM input types and one route-selected listener; it is not an audio ACK. Six observed acknowledgements were rejected as invalid-payload; their cause remains unresolved. The dashboard's `local=1` handoff changes navigation only; the existing loopback/authentication gate and gateway denial remain unchanged. The plain MO2 ZIP contains CHIM server data and may trigger MO2's Skyrim content warning; the FOMOD crash reported for v0.1.7 remains unresolved. Local fixtures do not prove live DB writes/concurrency, provider behavior, ACK/input delivery, installed dashboard authentication, native log delivery, or in-game acceptance. Test only in an isolated environment.
